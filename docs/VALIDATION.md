Version 0.2.0.8 queues layout only for explicit Fit/Reset actions. Fit requests the full raw display dimensions converted to view pixels immediately, regardless of pin/display mode. Resize limits remain flexible, and Fit does not call CenterWindowAsync. Only Reset requests the compact size and centering. Pinning, opening/closing Game Bar, and DPI changes create no automatic resize; hidden/display changes cancel stale requests. Coverage reporting checks position as well as dimensions, so a full-sized surface shifted upward 44 pixels is not reported as aligned. Focused native contracts cover that offset, fractional DPI, immediate requests, latest-action priority, cancellation, and absence of automatic requests after visibility changes. The subsequent user screenshot and local logs show content at (0,46), 2558x1394 on a 2560x1440 display at scale 1. New chrome diagnostics record the UWP title-bar height/visibility/extension state and full-screen state. The user's manual test could cover the top or bottom, but not both simultaneously. Read-only SDK metadata inspection found no outgoing host position/title-bar command; the private widget SetWindowBounds belongs to incoming state-notification interfaces and was not invoked as a spoofed positioning workaround.
